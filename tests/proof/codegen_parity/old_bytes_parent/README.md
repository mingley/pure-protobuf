# Older parent control

`bytes_old_parent.rs` was generated by the unchanged pbrs generator at
`6f9798aa2935e5b50603b96a650bf4432ce779bd`, before `Config::bytes` was added.
`manifest.json` records the generator, schema and generated-source hashes.
The generator used `--no-default-features --features codegen,json,text`.

The source maps `proof.bytes.Child` to `crate::proof::bytes::Child`, supplied
by the current selected-bytes consumer. It preserves the actual older parser
shape. The build script also generates a current unconfigured parent. The
consumer checks both parents' values and ownership behavior; unrelated
generator improvements may legitimately change the current source text.

The runtime control checks correct values and the ownership difference:
repeated/map child payloads copy shared input through this older parent, while
its lazy singular child retains a shared window. New selected bindings pass
shared wire through affected eager children. The new option does not promise
zero-copy payloads through every older or differently configured parent.

To regenerate with the recorded generator and protoc, from the repository root:

```sh
protoc -I tests/proof/codegen_parity/proto \
  --plugin=protoc-gen-pbrs=/path/to/the/recorded/protoc-gen-pbrs \
  --pbrs_opt=stubs=none --pbrs_opt=no_reflect=true \
  --pbrs_opt=extern_path=.proof.bytes.Child=crate::proof::bytes::Child \
  --pbrs_out=tests/proof/codegen_parity/old_bytes_parent \
  tests/proof/codegen_parity/proto/bytes_old_parent.proto
```

Keep only the parent source and update the manifest after verifying the
generator hash. This control deliberately retains generated source rather
than requiring an older compiler during every test run.
