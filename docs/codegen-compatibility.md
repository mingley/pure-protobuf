# Codegen Compatibility: Upstream Rust Shared Consumers

This document details the compatibility between `pure-protobuf` (`pbrs`) and the official Google Protocol Buffers Rust API (`protocolbuffers/protobuf`), explaining the relationship between internal kernel layouts and application-level traits, the 19 verified shared test suites, and the rationale for excluding C/arena internals.

---

## 1. Architecture: Kernel Layer vs Application Trait Layer

Google's official Rust Protocol Buffers implementation is architecturally separated into two distinct layers:

```
+-------------------------------------------------------------------------+
|                  Application Layer (rust/test/shared)                   |
|   Traits: Parse, Serialize, Clear, as_view(), as_mut(), proto! macro   |
|   Types:  ProtoStr, ProtoBytes, RepeatedView, Mut<'a, T>, View<'a, T>    |
+-------------------------------------------------------------------------+
                                    |
          +-------------------------+-------------------------+
          |                                                   |
          v                                                   v
+-------------------------------+             +-------------------------------+
|      Google upb Kernel        |             |     pure-protobuf (pbrs)      |
|         (rust/upb)            |             |        (src/lib.rs)           |
+-------------------------------+             +-------------------------------+
| - C library FFI (links=upb)   |             | - 100% Safe, idiomatic Rust  |
| - upb_Arena allocations       |             | - Standard Rust allocations   |
| - Raw C struct offsets        |             | - Struct field & slot layout  |
| - MiniTable FFI decode/encode |             | - Stand-in MiniTable runtime  |
| - Arena-fusing memory model   |             | - RAII / Drop memory safety   |
+-------------------------------+             +-------------------------------+
```

### The Kernel Layer (`rust/upb`)
In upstream Google protobuf, the default open-source kernel is `kernel=upb`, backed by the `upb` C library. The Rust binding is a thin FFI wrapper:
- Messages are represented as `OwnedMessageInner { ptr: *mut c_void, arena: Arena }`.
- Serialization and deserialization call C FFI (`upb_Decode`, `upb_Encode`) passing raw `upb_MiniTable` pointers.
- Submessages and repeated fields borrow memory directly from the parent message's C arena.
- Tests in `rust/test/upb/` assert raw C arena lifetimes, arena fusing (`upb_Arena_Fuse`), pointer arithmetic, and internal C struct offsets.

### The Application Trait Layer (`rust/test/shared`)
The application-level trait layer defines what user-facing Rust code actually consumes:
- Message traits: `Parse`, `Serialize`, `Clear`, `Default`.
- Field accessors: Singular scalars, optional fields, repeated fields, map fields, and oneof enums.
- Proxied views and mutators: `as_view()`, `as_mut()`, `into_view()`, `into_mut()`, `View<'a, T>`, `Mut<'a, T>`.
- String and bytes wrappers: `ProtoStr`, `ProtoBytes`, `ProtoString`.
- The `proto!` macro DSL for declarative message construction.

### pure-protobuf's Approach
`pure-protobuf` implements the **application-level traits** in 100% pure, safe Rust. To allow code generated by Google's official `protoc --rust_out kernel=upb` compiler to run unchanged, `pure-protobuf` provides:
1. **Runtime remapping**: Exposes the kernel under `protobuf` via `extern crate pbrs as protobuf;` and the `grpc_remap/protobuf-shim` crate.
2. **MiniTable stand-in (`src/runtime.rs`)**: Emits and links the `MiniTable` symbols expected by `protoc --rust_out kernel=upb` gencode, redirecting decode/encode operations to `pbrs`'s pure-Rust parser and serializer.
3. **Idiomatic Rust memory model**: Replaces C arena allocations with standard Rust memory management (`Drop`, `Vec`, RAII), eliminating memory safety vulnerabilities, memory leaks, and C compilation dependencies.

## 3. Distinguishing Original Shared Consumers from Locally Ported Tests

The pure-protobuf repository maintains two distinct test lanes for shared behavior:

1. **Original Shared Consumers (`rust_out_shared/`)**:
   - Uses the official Google code generator: `protoc --rust_out=... --rust_opt=experimental-codegen=enabled,kernel=upb`.
   - Links verbatim Google `rust/test/shared/*.rs` test files against `pbrs` using `extern crate pbrs as protobuf;`.
   - Proves that external code compiled by Google's official compiler can run on top of the pure-protobuf runtime without modification.
   - Executed via `./scripts/test-rust-out-shared.sh`.

2. **Locally Ported Behavioral Suite (`tests/google_shared.rs`)**:
   - Uses pure-protobuf's native compiler plugin: `protoc-gen-pbrs`.
   - Contains 38 in-tree integration tests exercising the same behavioral scenarios without requiring the `googletest` test runner crate or C-style MiniTable symbols.
   - Validates that pure-protobuf's own compiler plugin emits types that conform to the exact same application behavioral specification.
   - Executed via `cargo test --test google_shared`.

## 4. Why C and Arena Internals (`rust/test/upb/`) are Excluded

Google's repository contains tests under `rust/test/upb/` and `upb/test/`. These are intentionally excluded from `pure-protobuf`:

1. **Different Memory Architectures**:
   - `upb` allocates all messages on a C arena (`upb_Arena`). In `upb`, dropping an inner message is a no-op; the entire memory is freed only when the root arena is destroyed.
   - `pure-protobuf` uses standard Rust ownership (`Drop`, `Vec`, `Box`). Allocations are freed deterministically via RAII.
   - Tests in `rust/test/upb/` assert raw C arena fusing (`upb_Arena_Fuse`), raw C FFI pointer offsets, C minitable layout packing, and `OwnedMessageInner` C struct internals. These tests exercise C implementation details that do not exist in pure Rust.

2. **Absence of C FFI Hazards**:
   - The upb tests verify raw pointer safety, memory corruption edge cases during arena resizing, and FFI boundary contracts. Because `pure-protobuf` is implemented entirely in safe Rust (with localized, audited unsafe blocks strictly commented with `SAFETY`), C arena tests are inapplicable.

## 6. Continuous Verification

1. **Local Execution**:
   ```bash
   ./scripts/build-pinned-protoc.sh
   PROTOC="$PWD/target/pinned-protoc-build/protoc" ./scripts/test-rust-out-shared.sh
   ```
   The first command verifies the upstream source SHA and reuses the cached CMake compiler when available. The runner requires that compiler's pinned version and built-in `--rust_out`; Ubuntu's `protobuf-compiler` 3.21 has neither. It runs `cargo test` across all 19 crates in `rust_out_shared/` using `--offline` where appropriate, validates `grpc_remap/protobuf-shim`, and fails if 0 tests run or any crate fails. The script derives exact pins at run time (protoc `vendor/google/PIN` @ `vendor/google/SHA`, generator flags `--rust_opt=experimental-codegen=enabled,kernel=upb`, pbrs version from the root `Cargo.toml`, repo SHA with a dirty-worktree marker when needed), reports per-crate results, prints every exclusion with owner/reason/task, and verifies the upstream `rust/test/shared` inventory is fully accounted for (19 included + 5 excluded files) so new upstream suites cannot be silently skipped.

2. **Automated CI Workflow**:
   `.github/workflows/compatibility.yml` runs weekly on schedule (Sunday at 04:00 UTC) and on manual `workflow_dispatch`:
   - Builds or restores the pinned protoc with built-in Rust output before running `./scripts/test-rust-out-shared.sh` across all 19 crates, including the scheduled Miri lane's shared-consumer subset.
   - Verifies upstream pin integrity (`vendor/google/PIN`, `vendor/google/SHA`).
   - Verifies proto schema and shared test source drift against the upstream pin.
   - Runs committed output and stub flavour drift checks.
   - Reports any new upstream release tags as non-blocking advisory notices.

## 7. Generated-Code and Runtime Evolution Matrix

`pure-protobuf` defines explicit compatibility boundaries across generated code versions, schema revisions, and runtime kernels. The supported and explicitly unsupported combinations are summarized below:

| Combination | Status | Guarantee & Behavior |
|---|:---:|---|
| **Old-Generated Code + New Runtime** | **Supported** | Code generated by earlier versions of `protoc-gen-pbrs` continues to compile and execute without regression against newer `pbrs` runtime releases within the same major version. Backward compatibility of runtime helper types (`pbrs::rt::*`, `pbrs::gen_support::*`) is strictly maintained. |
| **Regenerated Code + Current Runtime** | **Supported** | Standard development workflow. Code regenerated by `protoc-gen-pbrs` targets the matching `pbrs` runtime version, leveraging optimal wire decoders, packed memcpy fast-paths, and current stub generators. |
| **New-Generated Code + Old Runtime** | **Unsupported** | The inverse combination is explicitly unsupported. Code generated by a newer compiler may emit references to newly introduced runtime helpers or performance intrinsics. Attempting to link against an older runtime fails predictably at compile time with missing item or trait implementation errors. |
| **Google C/upb Kernel ABI (`kernel=upb`)** | **Unsupported** | `pure-protobuf` is 100% pure, safe Rust. It does NOT implement raw C FFI struct offsets, `upb_Arena` arena-fusing, or `OwnedMessageInner` C pointers. Upstream C/upb internal ABI compatibility is excluded by architectural design. |
| **crates.io `protobuf` 4.x Direct Linkage** | **Unsupported** | The crates.io `protobuf` 4.x crate is an FFI wrapper around Google's internal C/upb engine. While `pure-protobuf` implements the exact Google v4 application trait specification (`Parse`, `Serialize`, `Clear`, `proto!`), its crate identity is `pbrs`. Renaming or remapping is supported via `grpc_remap/protobuf-shim`, but internal symbols must not be mixed. |

## 8. Schema Evolution & Wire Invariants (CG-11 Verification)

The pure-protobuf test suite under `tests/codegen_compat.rs` continuously validates schema evolution across frozen versioned fixtures (`tests/fixtures/codegen-compat/v1/` and `v2/`):

### 8.1 Forward Compatibility: Old Consumer Reading New Wire Data
- **Unknown Field Preservation**: When a v1 consumer reads wire data containing fields introduced in v2 (e.g. tags 12, 13, 14, 15, 16), the unknown fields are captured in `msg.unknown` (`UnknownFields`).
- **Round-Trip Fidelity**: Re-serializing the v1 message preserves all unknown fields bit-for-bit. A subsequent v2 deserializer recovers all newly added fields with zero data loss.
- **Open Enum Forward Compatibility**: Newly added enum variants in proto3 (e.g. `STATUS_SUSPENDED = 3`, `STATUS_ARCHIVED = 4`) are parsed into `Status(3)` without error and preserved across round-trips.
- **Oneof Forward Compatibility**: Newly added branches in a `oneof` (e.g. tag 16) are preserved as unknown fields; older oneof branches remain cleanly unset.

### 8.2 Backward Compatibility: New Consumer Reading Old Wire Data
- **Absence and Default Values**: When a v2 consumer reads wire data from v1:
  - Missing explicit presence (`optional`) fields report `has_*() == false` and return default zero/empty values.
  - Missing implicit presence scalars return standard proto3 defaults (0, empty string, empty bytes).
  - Missing repeated collections and maps report `.is_empty() == true`.
- **Reserved / Retired Fields**: Fields present in v1 that are retired and declared `reserved` in v2 (e.g. tag 11 `legacy_field`) are safely stored in v2's unknown fields and survive round-trips back to v1.

### 8.3 Presence Semantics & Mutation Invalidation
- **Presence Transitions**: Explicit optional fields transition deterministically between set (`has_*() == true`) and cleared (`clear_*()` -> `has_*() == false`).
- **Oneof Invariant**: Setting any alternative in a `oneof` immediately clears all sibling alternatives and dirty flags.
- **Cache Invalidation**: `pure-protobuf` generated messages maintain an internal `CachedSize`. Every field mutation (`set_*`, `_mut()`, `clear_*`, `clear()`) invalidates the cached length, guaranteeing that subsequent `compute_size()` and `serialize()` calls reflect exact updated payload sizes.

### 8.4 gRPC Service Stub Evolution (All 4 Call Shapes)
Both native `pbrs-grpc` (kernel) and `protobuf-tonic` (tonic) stub flavours generate consistent, strongly typed client and server stubs for all four canonical gRPC communication patterns:

```text
1. Unary:                   rpc UnaryCall (Req) returns (Resp);
2. Client-Streaming:        rpc ClientStreamCall (stream Req) returns (Resp);
3. Server-Streaming:        rpc ServerStreamCall (Req) returns (stream Resp);
4. Bidirectional-Streaming: rpc BidiStreamCall (stream Req) returns (stream Resp);
```

- **Additive RPC Evolution**: Adding new methods in v2 (e.g. `NewUnaryCall`, `NewServerStreamCall`) preserves existing method signatures.
- **Unimplemented Fallback**: Service handler traits provide default implementations returning `Status::unimplemented()`. Calling an unhandled or newer method on an older service implementation returns `Code::Unimplemented` safely without connection teardown or panic.

## 9. SemVer and ABI Expectations

### 9.1 Application-Level Compatibility vs Internal C ABI
- **Application Trait Contract**: Code written against the Google protobuf v4 application API (`Parse`, `Serialize`, `Clear`, `CopyFrom`, `MergeFrom`, `as_view()`, `as_mut()`, `proto!`) compiles and behaves identically on `pure-protobuf`.
- **No C/upb ABI Leakage**: Code that relies on C arena pointers, `upb_Arena_Fuse`, raw memory offsets, or private upb struct representations is fundamentally incompatible with pure-protobuf's memory-safe, RAII-based architecture.
- **Gencode Version Assertion**: The runtime provides `pbrs::__internal::assert_compatible_gencode_version(&str)` as a non-failing compatibility assertion for official `protoc --rust_out` generated code, acknowledging application-level v4 compatibility while avoiding false couplings to Google internal release trains.
