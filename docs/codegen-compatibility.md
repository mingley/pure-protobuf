# Codegen Compatibility: Upstream Rust Shared Consumers

`pbrs` tests its own generated messages and Google's unmodified
`protoc --rust_out` output separately. Google's output uses the compatibility
runtime; the table below lists the test lanes and supported consumers.

At audited commit `37683917`, the
[compatibility CI run](https://github.com/mingley/pure-protobuf/actions/runs/36594563929)
failed `test_map_int32_enum`: the raw map reported one entry but iteration
returned none. The run stopped in the first suite (34 passed, 1 failed).
The [enum-map repair](evidence/shared-map-recovery.md) and
[closed-enum follow-up](evidence/closed-enum-recovery.md) subsequently passed
all 233 original tests, with ordinary and Miri runs recorded at their source revisions.

## 1. Architecture: Kernel Layer vs Application Trait Layer

Google's Rust Protocol Buffers stack has two practical layers:

| Layer | What it contains | What `pbrs` does |
|---|---|---|
| Application trait layer (`rust/test/shared`) | `Parse`, `Serialize`, `Clear`, `as_view()`, `as_mut()`, `proto!`, `ProtoStr`, `ProtoBytes`, `RepeatedView`, `Mut<'a, T>`, and `View<'a, T>` | Implements these traits for generated messages. |
| Kernel layer (`rust/upb`) | C `upb` allocation, arenas, raw pointers, MiniTables, and internal struct offsets | Provides a separate compatibility runtime and MiniTable implementation. |

```text
+-------------------------------------------------------------------------+
|                  Application Layer (rust/test/shared)                   |
|   Traits: Parse, Serialize, Clear, as_view(), as_mut(), proto! macro   |
|   Types:  ProtoStr, ProtoBytes, RepeatedView, Mut<'a, T>, View<'a, T>    |
+-------------------------------------------------------------------------+
                                    |
          +-------------------------+-------------------------+
          |                                                   |
          v                                                   v
+-------------------------------+             +-------------------------------+
|      Google upb Kernel        |             |     pure-protobuf (pbrs)      |
|         (rust/upb)            |             |        (src/lib.rs)           |
+-------------------------------+             +-------------------------------+
| - C library FFI (links=upb)   |             | - pbrs runtime                |
| - upb_Arena allocations       |             | - Standard Rust allocations   |
| - Raw C struct offsets        |             | - Struct field & slot layout  |
| - MiniTable FFI decode/encode |             | - Stand-in MiniTable runtime  |
| - Arena-fusing memory model   |             | - RAII / Drop memory safety   |
+-------------------------------+             +-------------------------------+
```

### The Kernel Layer (`rust/upb`)

Upstream Google protobuf uses `kernel=upb` by default in open source. That kernel is backed by the `upb` C library, and the Rust binding is a thin foreign function interface (FFI) wrapper:

- Messages use `OwnedMessageInner { ptr: *mut c_void, arena: Arena }`.
- Decode and encode call C FFI (`upb_Decode`, `upb_Encode`) with raw `upb_MiniTable` pointers.
- Submessages and repeated fields borrow memory directly from the parent message's C arena.
- Tests in `rust/test/upb/` assert C arena lifetimes, arena fusing (`upb_Arena_Fuse`), pointer arithmetic, and internal C struct offsets.

### The Application Trait Layer (`rust/test/shared`)

The shared tests describe what user-facing Rust code consumes:

- Message traits: `Parse`, `Serialize`, `Clear`, and `Default`.
- Field accessors: singular scalars, optional fields, repeated fields, map fields, and oneof enums.
- Proxied views and mutators: `as_view()`, `as_mut()`, `into_view()`, `into_mut()`, `View<'a, T>`, and `Mut<'a, T>`.
- String and bytes wrappers: `ProtoStr`, `ProtoBytes`, and `ProtoString`.
- The `proto!` macro domain-specific language (DSL) for declarative message construction.

### pure-protobuf's Approach

`pbrs` implements the application-level traits. To let code generated by `protoc --rust_out kernel=upb` run unchanged, it provides:

1. **Runtime remapping.** Consumers can expose the runtime under `protobuf` with `extern crate pbrs as protobuf;` and the `grpc_remap/protobuf-shim` crate.
2. **MiniTable stand-in (`src/runtime.rs`).** `pbrs` emits and links the `MiniTable` symbols expected by `protoc --rust_out kernel=upb` generated code. Decode and encode then route to the pbrs parser and serializer.
3. **Rust ownership.** The compatibility runtime uses Rust-owned storage and an arena stand-in. It removes the C compilation dependency, but still contains unsafe pointer and lifetime operations with their own proof obligations; see [unsafe-invariants.md](unsafe-invariants.md).

## 4. Why C and Arena Internals (`rust/test/upb/`) are Excluded

Google's repository also contains tests under `rust/test/upb/` and `upb/test/`. `pure-protobuf` intentionally excludes them because they check implementation details of the C kernel, not the Rust application API.

1. **Different memory architecture.**
   - `upb` allocates all messages on a C arena (`upb_Arena`). Dropping an inner message is a no-op; memory is freed only when the root arena is destroyed.
   - `pure-protobuf` uses standard Rust ownership (`Drop`, `Vec`, `Box`). Allocations are freed deterministically through RAII.
   - `rust/test/upb/` asserts raw C arena fusing (`upb_Arena_Fuse`), raw C FFI pointer offsets, C MiniTable layout packing, and `OwnedMessageInner` C struct internals. Those tests depend on upb-specific layouts and arena behavior.

2. **Runtime-specific safety tests.**
   - The upb tests verify raw pointer safety, memory corruption edge cases during arena resizing, and FFI boundary contracts.
   - `pure-protobuf` is implemented in Rust, with localized audited `unsafe` blocks documented by strict `SAFETY` comments. Tests for the compatibility runtime are listed in [unsafe invariants](unsafe-invariants.md).

## 6. Continuous Verification

### Local execution

```bash
./scripts/build-pinned-protoc.sh
PROTOC="$PWD/target/pinned-protoc-build/protoc" ./scripts/test-rust-out-shared.sh
```

The first command verifies the upstream source SHA and reuses the cached CMake compiler when available. The runner requires that compiler's pinned version and built-in `--rust_out`; Ubuntu's `protobuf-compiler` 3.21 has neither.

The script:

- runs `cargo test` across all 19 crates in `rust_out_shared/`, using `--offline` where appropriate;
- validates `grpc_remap/protobuf-shim`;
- fails if 0 tests run or any crate fails;
- derives exact pins at run time: protoc `vendor/google/PIN` @ `vendor/google/SHA`, generator flags `--rust_opt=experimental-codegen=enabled,kernel=upb`, the `pbrs` version from the root `Cargo.toml`, and the repo SHA with a dirty-worktree marker when needed;
- reports per-crate results;
- prints every exclusion with owner, reason, and task;
- verifies the upstream `rust/test/shared` inventory is fully accounted for: 19 included files plus 5 excluded files, so new upstream suites cannot be silently skipped.

### Automated CI workflow

`.github/workflows/compatibility.yml` runs weekly on Sunday at 04:00 UTC and on manual `workflow_dispatch`.

It:

- builds or restores the pinned protoc with built-in Rust output before running `./scripts/test-rust-out-shared.sh` across all 19 crates, including the scheduled Miri lane's shared-consumer subset;
- verifies upstream pin integrity (`vendor/google/PIN`, `vendor/google/SHA`);
- verifies proto schema and shared test source drift against the upstream pin;
- runs committed output and stub flavour drift checks;
- reports any new upstream release tags as non-blocking advisory notices.

## 7. Generated-Code and Runtime Evolution Matrix

`pure-protobuf` sets explicit compatibility boundaries across generated code versions, schema revisions, and runtime kernels:

| Combination | Status | Guarantee and behavior |
|---|:---:|---|
| **Old-Generated Code + New Runtime** | **Tested fixtures** | Frozen `protoc-gen-pbrs` consumers are checked against the current runtime. This is a compatibility goal with concrete fixtures, not a guarantee for every historical generator or every future 0.x release. See the [support policy](support-policy.md). |
| **Regenerated Code + Current Runtime** | **Supported** | This is the standard development workflow. Code regenerated by `protoc-gen-pbrs` targets the matching `pbrs` runtime version and can use optimal wire decoders, packed memcpy fast paths, and current stub generators. |
| **New-Generated Code + Old Runtime** | **Unsupported** | The inverse combination is explicitly unsupported. A newer compiler may emit references to newly introduced runtime helpers or performance intrinsics. Linking against an older runtime fails predictably at compile time with missing item or trait implementation errors. |
| **Google C/upb Kernel ABI (`kernel=upb`)** | **Unsupported** | `pure-protobuf` does not implement raw C FFI struct offsets, `upb_Arena` arena-fusing, or `OwnedMessageInner` C pointers. Upstream C/upb internal ABI compatibility is excluded by design. |
| **crates.io `protobuf` 4.x Direct Linkage** | **Unsupported** | The crates.io `protobuf` 4.x crate is an FFI wrapper around Google's internal C/upb engine. `pure-protobuf` implements the Google v4 application trait specification (`Parse`, `Serialize`, `Clear`, `proto!`), but its crate identity is `pbrs`. Renaming or remapping is supported via `grpc_remap/protobuf-shim`; internal symbols must not be mixed. |

## 8. Schema Evolution & Wire Invariants (CG-11 Verification)

The tests in `tests/codegen_compat.rs` validate schema evolution across frozen versioned fixtures in `tests/fixtures/codegen-compat/v1/` and `tests/fixtures/codegen-compat/v2/`.

### 8.1 Forward Compatibility: Old Consumer Reading New Wire Data

- **Unknown field preservation.** When a v1 consumer reads wire data containing fields added in v2, such as tags 12, 13, 14, 15, and 16, the unknown fields are captured in `msg.unknown` (`UnknownFields`).
- **Round-trip fidelity.** Re-serializing the v1 message preserves all unknown fields bit-for-bit. A later v2 deserializer recovers all newly added fields with zero data loss.
- **Open enum forward compatibility.** Newly added enum variants in proto3, such as `STATUS_SUSPENDED = 3` and `STATUS_ARCHIVED = 4`, parse into `Status(3)` without error and are preserved across round-trips.
- **Oneof forward compatibility.** Newly added branches in a `oneof`, such as tag 16, are preserved as unknown fields. Older oneof branches remain cleanly unset.

### 8.2 Backward Compatibility: New Consumer Reading Old Wire Data

- **Absence and defaults.** When a v2 consumer reads v1 wire data:
  - missing explicit-presence (`optional`) fields report `has_*() == false` and return default zero or empty values;
  - missing implicit-presence scalars return standard proto3 defaults: `0`, empty string, or empty bytes;
  - missing repeated collections and maps report `.is_empty() == true`.
- **Reserved and retired fields.** Fields present in v1 but retired and declared `reserved` in v2, such as tag 11 `legacy_field`, are stored safely in v2's unknown fields and survive round-trips back to v1.

### 8.3 Presence Semantics & Mutation Invalidation

- **Presence transitions.** Explicit optional fields transition deterministically between set (`has_*() == true`) and cleared (`clear_*()` -> `has_*() == false`).
- **Oneof invariant.** Setting any alternative in a `oneof` immediately clears all sibling alternatives and dirty flags.
- **Cache invalidation.** Generated messages maintain an internal `CachedSize`. Every field mutation (`set_*`, `_mut()`, `clear_*`, `clear()`) invalidates the cached length, so later `compute_size()` and `serialize()` calls reflect the updated payload exactly.

### 8.4 gRPC Service Stub Evolution (All 4 Call Shapes)

Both native `pbrs-grpc` (kernel) and `protobuf-tonic` (tonic) stub flavours generate consistent, strongly typed client and server stubs for all four canonical gRPC communication patterns:

```text
1. Unary:                   rpc UnaryCall (Req) returns (Resp);
2. Client-Streaming:        rpc ClientStreamCall (stream Req) returns (Resp);
3. Server-Streaming:        rpc ServerStreamCall (Req) returns (stream Resp);
4. Bidirectional-Streaming: rpc BidiStreamCall (stream Req) returns (stream Resp);
```

- **Additive RPC evolution.** Adding new methods in v2, such as `NewUnaryCall` and `NewServerStreamCall`, preserves existing method signatures.
- **Unimplemented fallback.** Service handler traits provide default implementations returning `Status::unimplemented()`. Calling an unhandled or newer method on an older service implementation returns `Code::Unimplemented` safely, without connection teardown or panic.

## 9. SemVer and ABI Expectations

### 9.1 Application-Level Compatibility vs Internal C ABI

- **Application trait contract.** `pbrs` targets the Google protobuf v4 application API (`Parse`, `Serialize`, `Clear`, `CopyFrom`, `MergeFrom`, `as_view()`, `as_mut()`, `proto!`). The included tests, documented exclusions, and current failures define the verified surface; the experimental runtime is not yet behaviorally complete.
- **No C/upb ABI leakage.** Code that relies on C arena pointers, `upb_Arena_Fuse`, raw memory offsets, or private upb struct representations is fundamentally incompatible with pure-protobuf's memory-safe, RAII-based architecture.
- **Gencode version assertion.** `pbrs::__internal::assert_compatible_gencode_version(&str)` is currently non-failing. It does not prove compatibility with arbitrary Google releases; pinned generated consumers and release-drift checks must supply that evidence.
