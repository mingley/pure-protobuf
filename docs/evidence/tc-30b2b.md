# TC-30b2b: inbound compression opt-out for opaque tonic services

Native `accept_compressed(false)` admits identity requests on unchanged tonic-generated services. Disabled nonidentity request headers reject in the native kernel before Tower readiness and handler entry. A compressed flag under a missing/identity coding header is knowable only while reading the message prefix; that rejection can follow readiness/handler entry for streaming methods. The cold guard withholds an invalid prefix and preserves earlier admitted messages and original DATA views.

Only opt-out canonicalizes the identity aliases already admitted by the native parser. Response `grpc-accept-encoding` headers and trailers advertise identity. Negotiated output `grpc-encoding`, encoded DATA, status/details and user metadata remain unchanged. Native cap selection is value-based: a cap whose value differs from the native default adds that native limit over tonic's private decoder; a default-valued setter is indistinguishable from an unchanged cap. Tests exercise a private tonic decoder above 4 MiB without imposing that unchanged native default.
