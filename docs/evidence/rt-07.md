# RT-07: overload fairness and slow-peer isolation

## Scope

Card RT-07 ("Verify overload fairness and slow-peer isolation") at base
`016898c1`. This increment builds on the three recorded partials without
regressing them: the bounded separate-process native mixed-load diagnostic
(`2584e5c1`), the server `on_server_queue_wait` post-admission scheduling
signal, and the `ByteBudgetTracker` exact peak gauges. All work is confined
to `pbrs-grpc/tests/resource_bounds.rs`,
`rpc-bench/scenarios/fairness.json`, and this note.

## Method

Extended the `resource_bounds` CI smoke harness (`cargo test -p pbrs-grpc
--test resource_bounds`):

- `PermitProbe` now records server post-admission scheduling delay per
  `SayHello` call via `on_server_queue_wait`, plus a monotonic admitted-stream
  counter (`wait_for_started`). It is not full listener/transport queue time;
  rejected calls emit no sample.
- `FairnessRecord::report` now records, per probe phase: offered/success/
  rejected counts, p99, client scheduling lag, client pool wait, server
  scheduling samples/max/p99, sampled and exact (`peak_allocated`) byte peaks
  against the budget, byte-permit token peak/live counts, admitted-stream
  started/peak/active counts, and start/peak RSS.
- Added `test_mixed_bulk_slow_idle_reset_fairness`: 2 bulk server streams, a
  paused slow reader, a dripping slow writer, 4 idle peers and a raw
  RST_STREAM(CANCEL) storm overlap 32 scheduled small unary probes under
  Profile-2-shaped limits (16 conns, 32 RPCs, 64 streams, 1 MiB/256 KiB
  windows, 64 KiB send buffer, bounded reset tracking, 2 MiB byte budget).
- Every existing fairness/overload phase now asserts the server scheduling
  bound (max < 100 ms) and exact byte-peak containment; storm-free phases
  assert exactly one server sample per admitted probe, and the overload burst
  asserts zero samples for 24 rejections.

Two findings shaped the assertions. First, admitted storm resets share the
`SayHello` method, so storm phases observe hundreds of extra server samples
(374-498); the universal invariant is `samples >= admitted`, with exact
equality asserted only outside storms. Second, server-side streams drain
quickly into wire buffers, so the mix test barriers on admission
(`wait_for_started(4)`, writer still holding) while app-level overlap is
proven by bulk reads, drips and resets counted during the probe window.

Overlap and recovery proofs: bulk reads during probes 24 (bulk) and 18
(mixed, bound >= 16); resets during probes 341 (storm) and 294 (mixed, bound
>= 16); writer drips 3/3 during probes; slow reader/writer payloads drain
exactly in order after probes; every phase ends quiescent (allocated bytes 0,
byte-permit tokens 0, active streams 0) with a successful post-drain probe.
Overload rejections cite the violated limit (`too many concurrent RPCs` /
`transport byte budget exceeded`), never reach the handler (0 unary payload
bytes observed), and release immediately on close/drop.

## Per-accept verdicts

1. Explicit violation status, competing calls progress within budget: PASS.
   24/24 burst rejections carry `RESOURCE_EXHAUSTED` naming the limit with no
   server scheduling sample and no handler bytes; all 32/32 probes succeed in
   every hostility mix (bulk, slow reader, slow writer, idle, storm, combined)
   within the preregistered p99/scheduling budgets.
2. Queue delay, p99, rejected calls, RSS and permits recorded per phase: PASS.
   Every report line carries all five dimensions plus exact byte/token peaks;
   no aggregate throughput is used as a starvation or growth proxy.
