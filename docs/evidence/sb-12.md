# SB-12 connection scale and cold-start measurements

Date: 2026-09-28. Base SHA:
`b4c6a0099e2b9f4f0d3f19a78a29d13d5e39f9df`. Host: Apple Silicon macOS,
shared/contended. These are dev-loop/contended-host diagnostics, not
claim-grade resource ceilings.

## Harness

Added `rpc-bench scale`:

```sh
rpc-bench scale \
  --transport <native|tonic> \
  --connections <N> \
  --streams <N> \
  [--tls-cert FILE --tls-key FILE --tls-ca FILE --tls-server-name NAME] \
  [--repeats N] \
  --output target/sb12/<row>.json
```

The scale cell starts an in-process loopback server, records current-process RSS
with the existing `resources::ResourceSnapshot`, opens idle client connections,
opens server-streaming calls, and records time-to-first empty unary RPC. The RSS
deltas include client and server in one process, so they are useful for
same-host comparison but are not an isolated endpoint memory claim.

Host limits recorded in `target/sb12/host-limits.txt`:

| Limit | Value |
|---|---:|
| `ulimit -n` | 1,048,575 |
| `kern.maxfiles` | 368,640 |
| `kern.maxfilesperproc` | 184,320 |
| ephemeral port range | 49,152-65,535 |

## 1k connection / 1k stream rows

Commands:

```sh
for t in native tonic; do
  for r in 1 2 3; do
    CARGO_BUILD_JOBS=3 cargo run --manifest-path rpc-bench/Cargo.toml --release -- \
      scale --transport=$t --connections=1000 --streams=1000 --repeats=5 \
      --output target/sb12/${t}-1000-r${r}.json
  done
done
```

| Transport | Idle bytes/connection (runs) | Median idle bytes/conn | Open-stream bytes (runs) | Median bytes/open stream | Median first RPC |
|---|---:|---:|---:|---:|---:|
| pbrs-grpc | 84,279 / 84,148 / 84,263 | 84,263 | 14,942 / 14,991 / 14,893 | 14,942 | 2.280 ms |
| tonic | 93,143 / 93,094 / 93,176 | 93,143 | 20,890 / 20,955 / 20,939 | 20,939 | 1.760 ms |

Read: pbrs-grpc used ~9.5% fewer bytes per idle connection and ~28.6% fewer
bytes per open stream in this same-process diagnostic, but its median
time-to-first-RPC was slower than tonic.

## 10k idle connection rows

The host allowed 10k client connections for both transports. To avoid adding

Read: the 10k idle row confirms the 1k memory ordering. It is a single repeat,
so do not use it as the primary SB-12 acceptance row.

## TLS handshake rate

Native TLS only:

```sh
CARGO_BUILD_JOBS=3 cargo run --manifest-path rpc-bench/Cargo.toml --release -- \
  scale --transport=native --connections=100 --streams=100 --repeats=50 \
  --tls-cert pbrs-grpc/tests/tls_data/server.crt \
  --tls-key pbrs-grpc/tests/tls_data/server.key \
  --tls-ca pbrs-grpc/tests/tls_data/ca.crt \
  --tls-server-name localhost \
  --output target/sb12/native-tls-100-r1.json
```

| Transport | TLS idle bytes/connection | TLS open-stream bytes | First RPC | Handshakes/s |
|---|---:|---:|---:|---:|
| pbrs-grpc | 140,083 | 20,480 | 4.949 ms | 1,937.9 |
| tonic | not run | not run | not run | not run |

Tonic TLS is intentionally not enabled in this harness because tonic TLS pulls a
C crypto provider, which violates the pure-Rust dependency policy for this
workspace. A standalone external tonic TLS harness would be a separate SB-12
extension.

## grpc-go

The pinned Go peer runs locally for interop/QPS harnesses, but no Go scale cell
was added in this pass. `rpc-bench scale` currently compares in-process native
and tonic transports. A Go row needs a separate-process scale protocol so RSS
deltas do not mix the Rust harness and Go runtime.

## Limits

- RSS is current-process RSS (`macos-mach`) and includes both loopback server
  and client.
- The connection count rows are closed-loop setup diagnostics, not steady-state
  soak/leak tests.
- The 10k rows are single-repeat probes and should be treated as limit
  confirmation, not acceptance-quality medians.
