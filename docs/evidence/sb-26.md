Historical map instruction counts have an additional reproducibility limit:
the common prost wire used randomized `HashMap` entry order. An identical
binary replay changed 512-entry decode by −22.05% and read-all by +7.80%.
SB-31 freezes entry order during fixture preparation and checks input
fingerprints across differential children and repeats. The original reports
remain historical diagnostics; they cannot qualify a map optimization under
the 1% control gate. This correction does not change shipping serialization,
the map equal-wire rejection, or the retained allocation and value checks.

Neither the transport-only native/prost profile nor full-native pbrs meets
the proposed P3 instruction limit (0.7×) or allocation limit (0.6×) on any
of its 122 measured pairs. Native/prost sparse streaming costs 1.773–2.023×
reference instructions and 2.310–2.314× allocated bytes. Full-native query
streaming uses 1.611–1.800× reference allocations. The six entity pairs have
lower observed costs in both native profiles, but still miss P3's margins.
These targets steer the plan; no binding benchmark threshold changed.

On the same native transport, switching prost messages to pbrs also costs
more allocations for all query and sparse variants in both shapes. Query
instruction ratios are 1.021–1.293× unary and 1.157–1.341× streaming, with
losses on all 96 query pairs. Entity ratios are lower, and sparse instructions
fall, but those gains do not remove the query or sparse-allocation losses.
The raw reports retain both message layers for independent recomputation.
