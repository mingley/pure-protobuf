# CL-08: direct prost encoding removes temporary payload buffers

The additive codec hook at candidate source
`2321d736c0e9ed1b3323d24d99b2cc437c594774` reduces allocations and allocated
bytes on all 122 eligible native prost RPC ledger rows against exact baseline
`cf3eee22c6b06324e299f81b76915651471d8025`. It does not complete CL-08:
64 rows are at or below tonic's allocated bytes, 58 still lose, and 12 map
profile rows remain blocked by the existing wire-work preflight. These are
source-pinned dev-loop diagnostics, not throughput, latency or CPU leadership.
The 20 primary instruction/allocation/byte controls pass, and both TC-03 cells
now meet byte parity. The unchanged complete comparison exits 1 on syscall/futex
regressions, including a tonic control. The coordinator rejected this standalone candidate for integration. The
source patch is retained as an experiment; no shipping performance merge is
authorized by these measurements.

## Hypothesis and reviewed implementation

Targets are C5/D4/A13 and the two TC-03 prost RPC shapes. The existing prost
`CodecMessage::encode_payload` creates a temporary payload `Vec`, then copies
it into the existing segmented frame's `BytesMut` head. Removing that temporary
buffer should save one allocation and its encoded length per uncompressed
message: two messages per unary RPC, five per four-response streaming RPC.
No allocator, threshold, workload, dependency or public protocol default changes.

The coordinator approved an additive default method:

```rust
fn encode_contiguous(&self, out: &mut BytesMut) -> Option<Result<(), Status>>;
```

The default returns `None` and leaves the buffer untouched. A codec overriding
it appends only payload bytes after the existing prefix; it cannot alter or
remove earlier bytes. Prost delegates directly to its existing safe
`Message::encode` implementation, preserving its `Status::internal` error
mapping. `SegSink` records the appended length. Failed batched appends use the
existing checkpoint rollback, preserving earlier complete frames. The default
native codec still uses its existing shared-segment path. Compression retains
materialization and its existing framing; limits are checked before encoding.
There is no pool, size cutoff, new unsafe code, or benchmark-specific branch.

The patch is restricted to `codec.rs`, `codec/prost.rs` and `wire/encode.rs`,
plus the two dedicated regressions. Client/server dispatch, streaming policies,
transport and benchmark collectors are unchanged. All 169 retained core,
manifest, lock, corpus and collector source pins match the baseline
([unchanged pins](cl-08/cl08-unchanged-input-pins.json)).

## Allocator-only ledger evidence

The frozen corpus registers 64 specimens, two shapes and both native-prost and
corresponding tonic-prost profiles: 256 profile rows. The 61 eligible specimens
are `query.d{3..8}.v{0..7}`, `entities.n{10,100,1000}` and `sparse.v{0..9}`.
The exact [row inventory](cl-08/cl08-ledger-rows.json) includes every eligible
row and the 12 blocked `maps.n{8,64,512}` profile/shape combinations.

The immutable before/after release binaries use the existing CLI directly:

```sh
devloop run-cell <row> --iters 64 --prepare-iters 128 --warmup 100
devloop run-cell <row> --iters 128 --prepare-iters 128 --warmup 100
```

Preparation, 100 warmup calls, full response equality/read validation, and the
counting allocator are unchanged. Each row has three repeats at both N values
on both revisions, with sequential paired revision order selected by a fixed
seed. The external [capture](cl-08/capture-ledger.py) retains complete stdout,
stderr, command, source, binary launch/after hashes and exit status. It changes
neither the shipping runtime nor the frozen collector.

The independent [64-specimen oracle](cl-08/cl08-inputs.rs) uses the existing
corpus preparation, complete-value/clone checks and stable non-map wire
fingerprints. Two oracle runs were byte-identical. Every raw child's existing
`__QUALIFICATION__` bytes/checksum/reply count matches this source-bound oracle.
The raw record's `oracle_input_wire_fingerprint` comes from the independent
oracle: the frozen RPC child does not itself print a fingerprint. Unchanged
corpus/source pins bind the input construction to both binaries.

The existing `run_pair` always applies `assert_equal_wire_work` before selecting
a transport/codec profile. Map wire lengths still differ by four bytes between
native and prost. Those 12 profile rows are blocked even for the prost pair;
this investigation does not bypass or relax that global preflight. The oracle
retains their negative qualification without entering a timing window.

The [representative pilot](cl-08/allocator-pilot/report.json) validated 32 child
launches in 18.37 seconds. The [full report](cl-08/allocator-ledger/report.json)
validated all 2,928 launches in 279.18 seconds, retaining
[raw evidence](cl-08/allocator-ledger/raw.jsonl). These elapsed values are noisy
shared-host run diagnostics. Ordinary jobs=1 builds were permitted concurrently;
there is no comparative wall-time claim. Ledger instructions are explicitly
`not_run`, not an every-ledger CPU improvement.

The separate [validator](cl-08/validate-ledger.py) reconstructs allocation and
byte medians from raw child counters, checks all unique row/N/repeat/revision
keys, commands, preflight records, source/fingerprint bindings and binary hashes.
Its [summary](cl-08/cl08-allocator-summary.json) reports the same outcome at
both N=64 and N=128:

| Native prost ledger result | Rows at each N |
|---|---:|
| Lower allocation count than baseline | 122/122 |
| Lower allocated bytes than baseline | 122/122 |
| Allocation-count regressions | 0 |

Every query unary and entity shape meets byte parity. Only ten query streaming

## Remaining sparse cost: bounded read-only attribution

At the pinned candidate, [dispatch disassembly](cl-08/cl08-sparse-dispatch.txt)
shows the native `Echo<Message<Sparse>>::DynService::dispatch` wrapper allocating
`0x7710` (30,480) bytes and copying that whole future. The large static Sparse
schema has 128 inline optional fields even when the encoded value is 108 bytes.
This proves one typed-future allocation site, not a complete allocation-stack
breakdown or a cross-stack explanation of the entire gap.

An initial grep incorrectly attributed outbound client/bidi channel construction
to a decoded response pump. That hypothesis was retracted after source review:
`FrameReader::finish_stream` returns `Streaming::from_wire`, with no intermediate
client response mpsc. Both frozen server application producers use capacity
8 channels; Tokio's 32-slot block layout is shared by both stacks and cannot
alone explain their byte difference. Future/task attribution belongs to the
coordinator's server lane; no client/server/stream source is edited here.

## Correctness and rollback

All 519 semantic tests passed with zero failures/ignores: 442 library tests
including five focused direct-frame tests, the external legacy codec consumer,
CL-07 raw-peer tests, prost four-shape integration and existing RPC/gap/hostile/
message-size gates ([raw log](cl-08/logs/cl08-semantic-gates.log)).

```sh
cargo test --locked -p pbrs-grpc --features prost --lib \
  --test cl08_contiguous --test prost_codec --test rpc --test gaps \
  --test hostile --test message_size --test cl07_preface -- --test-threads=1
cargo clippy --locked -p pbrs-grpc --features prost,copy-counts \
  --lib --test cl08_contiguous -- -D warnings
cargo fmt --package pbrs-grpc -- --check
cargo test --locked --manifest-path rpc-bench/Cargo.toml \
  --bin rpc-bench --test worker --test fairness
```

Strict [Clippy](cl-08/logs/cl08-clippy.log), [formatting](cl-08/logs/cl08-format.log),
and all 189 required [RPC benchmark tests](cl-08/logs/cl08-rpc-bench-gates.log)
passed. The semantic lib-test run without copy-counts emitted the pre-existing
unused-import warning at `copy_counts.rs:184`; the strict feature-enabled check
is clean. No unrelated lint suppression or source edit is added.

Regressions cover old third-party trait implementations, direct prefix/length
accounting, outbound rejection before encoding, unchanged gzip materialization,
partial failure between two complete batched messages followed by successful
wire delivery, and reference prost framing across length/varint boundaries up
to 1 MiB. Existing native sharing tests remain in the library suite. There is no
new unsafe code requiring Miri; the coordinator owns integrated broad F gates.

Owned Cargo artifacts peaked at 2,125,495,473 bytes below the assigned 2 GiB
limit after tests. Completed debug cache was removed before the release build;
the reused target then held 942 MiB. Build/gate logs are retained.

The candidate is rejected for integration. The existing 1% codec / 2% RPC
limits stay unchanged. Primary controls qualify only the observed allocation
improvement; CL-08 remains open for the failed full comparison, 58 remaining byte
losses, 12 blocked map profiles and all other original acceptance requirements.
No buffer pool or retained-memory guarantee is introduced.
