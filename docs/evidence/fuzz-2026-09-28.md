# Fuzz dev-loop evidence — 2026-09-28

This is a bounded dev-loop run, not the 24 CPU-hour qualification campaign.
Each target was run with one libFuzzer job/worker on the shared macOS host:

```bash
cargo +nightly fuzz run <target> -- -max_total_time=300 -jobs=1 -workers=1
```

## Crashes fixed

1. `grpc_wire` found a peer-input panic in `timeout::parse_timeout`:
   Base64 `PADJoQ==` (`3c 00 c9 a1`) split a UTF-8 scalar at a byte boundary.
   `parse_timeout` now splits the ASCII `grpc-timeout` grammar by bytes and
   rejects malformed non-ASCII tails. Regression:
   `pbrs-grpc/tests/regress_timeout.rs`.
2. `grpc_wire` found that public ASCII metadata insertion accepted non-ASCII
   header values that `Metadata::get` could not read back: Base64 `dn7Vsg==`
   (`76 7e d5 b2`). `Metadata::insert` and `Metadata::set` now reject values
   that fail `HeaderValue::to_str()`. Regression:
   `pbrs-grpc/tests/regress_metadata.rs`.
3. `grpc_wire` also exposed a nondeterministic fuzz-harness wall-clock oracle:
   Base64 `LS1gYGBgYGBgYGBgYGBgYGDgYGBgYGB8fA==` timed out the synthetic gzip-bomb
   assertion on a shared host. The harness now keeps the deterministic
   `RESOURCE_EXHAUSTED` bounded-decode assertion and does not assert elapsed
   wall time inside libFuzzer.

No minimized crash artifact is committed; the product regressions are captured
as deterministic tests and generated corpora/artifacts were left untracked and
cleaned after the run.
