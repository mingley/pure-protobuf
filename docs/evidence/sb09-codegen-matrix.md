# SB-09: codegen comparator matrix

**Status: broad local diagnostic, not a qualified performance campaign.**
The 2026-09-28 run covers 165 generator/corpus/repeat cells and records broad
pbrs compile-cost losses. It predates later GN optimizations; repeat the same
matrix to assess their combined effect. Raw artifact paths below refer to the
machine that produced the record, not guaranteed files in a fresh clone.

## What

Extended `bench/codegen/run.py` (~+1900 lines) from the CG-19 pbrs-only
flow to a generator matrix, all under `cases/<case>/gen/<name>/`:

- Message generators (`--generators`, default `pbrs`): `pbrs` (exact
  CG-19 flow), `prost` (prost-build 0.14.4), `buffa` (buffa-build 0.9.1),
  `v4` (pinned protoc 35.1 `--rust_out`, kernel=upb). Every phase is
  measured per cell: generation time/RSS, generated bytes, clean and
  incremental `cargo check`, release build time/RSS, binary size.
- Stub generators (`--stub-generators`, svc corpora only, compared
  separately): `pbrs-native`, `pbrs-tonic`, `tonic-build`.
- `--repeats N` (default 5) with seeded-random global execution order;
  `summary.json#matrix` reports median/min/max/stdev per metric plus the
  pbrs-vs-peer loss list. Case/generator exclusions record reasons under
  `#excluded` instead of failing.
- Four realistic corpora: `otlp` (30 msgs), `googleapis` (4),
  `envoy-core` (16), `envoy-discovery` (10). 27 hash-pinned `.proto`
  files (OTLP v1.7.0, googleapis, Envoy v1.39.1, udpa, xds,
  protoc-gen-validate v1.3.3) fetch on first use into
  `target/codegen-bench/vendor/` and re-verify SHA-256 every run; WKT
  comes from pinned `third_party/protobuf`. Every generator compiles
  the full closure; consumers roundtrip subset top-level messages.
- Per-generator output validation: exact file sets for pbrs (mirrored
  plus unique-stem flat files), prost (one per closure package, WKT
  extern-mapped), v4 (mirrored plus searched entrypoint); core-plus-aux
  for buffa (content-aware: extension-only and enum-only inputs).
- `bench/codegen/test_run.py`: 62 tests (11 realistic); `bench/codegen/
  README.md`: matrix usage and provenance docs.
- Drive-by product fix (required by the Envoy corpus): pbrs codegen now
  escapes keyword package segments (`src/codegen/naming.rs`
  `mod_ident`/`pkg_mod_path`, `descriptors.rs` emission, unit test);
  `envoy.type.v3` previously emitted uncompilable `pub mod type`.

## Accept mapping

- Equivalent work per message: every consumer constructs each message
  default, serializes, parses, re-serializes (prost/buffa/v4/pbrs all
  share this shape; stub consumers additionally build each service's
  server plus a lazy client). `release_smoke` executes each binary and
  requires stdout `1\n`: every roundtrip must run and every default
  message must serialize empty. No nonempty-field behavior is claimed.
- Five randomized repeats and loss reporting: done. Seeded global order
  (seed 190019), median/min/stdev per metric over n=5, and pbrs-vs-peer loss
  list under `summary.json#matrix.losses`. Standard deviation describes spread;
  it is not the paired 95% confidence interval required by the contract.
- Stubs compared separately: done (svc-small/svc-100 x 3 stub
  generators below; stub cells never mix with message cells).

## Results

Loss list: 61/240 peer-metric entries lose to pbrs, almost all in
generation time/RSS (peers' protoc/file-IO overhead vs in-process
pbrs); peers beat pbrs on 179/240, concentrated in check/build
time and RSS. The driver is output size: pbrs emits 10-290x more
bytes than prost (derive-heavy, monomorphized per message), so
downstream rustc work dominates. Example spread: 100/pbrs release
build stdev/mean 3.4%.

Reproduce (several hours; needs network once for the vendor fetch):

```sh
./scripts/codegen-bench.sh --case all \
  --generators pbrs,prost,buffa,v4 \
  --stub-generators pbrs-native,pbrs-tonic,tonic-build \
  --repeats 5 --out target/codegen-bench/sb09-evidence
```

## Scope and limitations

- Consumers cover subset top-level messages only; nested types are out
  of scope. Only default values run.
- `envoy-discovery` excludes `v4` (recorded): its flat namespace cannot
  hold the `PackageVersionStatus` enum defined by both
  `udpa/annotations` and `xds/annotations/v3` (E0659).
- Unqualified single-host diagnostic: no independent peer host; local
  registry/compiler caches may be warm (fresh target dir per cell).
