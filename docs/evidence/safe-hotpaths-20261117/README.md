This follow-up restores two documented runtime contracts and checks smaller
allocation and codec improvements. Each check belongs to the source revision
shown below. Component measurements are shared-host diagnostics; they do not
establish RPC throughput, a general lead over tonic/Prost, or release readiness.

## Connection metadata

[751276a3](https://github.com/mingley/pure-protobuf/commit/751276a395aba29cbed1c2869e146cc8d3a41a8c)
delays derived connection metadata until the transport scheme is known. A TLS
request with an existing context map receives TLS metadata without an earlier
derived cleartext entry. Explicit application overrides and completed
unknown-scheme request parts retain their behavior.

The [exact request gate](https://github.com/mingley/pure-protobuf/actions/runs/44035325229)
detects the failure on the unchanged parent and passes 21 unit tests, eight
native/tonic TCP, UDS, TLS and mTLS cases, formatting and strict library Clippy
on the candidate. The [combined runtime gate](https://github.com/mingley/pure-protobuf/actions/runs/44036933518)
passed 175 core and 886 gRPC library tests on Rust 1.85, native connection-info
and release allocation tests, and stable tonic integration and formatting.

## Connection-info component measurement

The identity-borrow experiment compares `56bc4e53` with `13109f6e`.
Repeated mTLS extension lookups measured a median 10.27 to 8.70 ns per lookup;
the candidate/baseline elapsed ratio was 0.8464. The matching A/A median was

## Owned scalar-map decoding

[f4e5fdb1](https://github.com/mingley/pure-protobuf/commit/f4e5fdb1812c942933df65a637647cd51ad69466)
avoids a parent-wire allocation when eagerly decoding map values whose schema
contains only singular scalars. Shared input keeps its existing windows.
Strings, bytes, repeated fields, nested values, extern types and MessageSet
values keep the existing parent-backing strategy.

The [generated-consumer gate](https://github.com/mingley/pure-protobuf/actions/runs/44036214749)
covers unknown fields, malformed descendants, required-value merges and
replacement, Rust 1.85, and byte-identical default/lazy output.
See the [full component screen](../owned-scalar-map-20261117/README.md) for
allocation counts, timings and unchanged-path controls. Regenerate owned
bindings to use the new decoder.

## Empty repeated fields

[cc502ed2](https://github.com/mingley/pure-protobuf/commit/cc502ed27ac4970fa2c8fbc08d846c6904da87ce)
returns an empty mutable slice directly for an unallocated repeated field.
The call requests zero allocations instead of one; existing reserved and
populated buffers retain their pointer and capacity.

The [debug/release detecting controls](https://github.com/mingley/pure-protobuf/actions/runs/44035054620)
fail on the old implementation and pass on the candidate. The
[candidate checks](https://github.com/mingley/pure-protobuf/actions/runs/44034323898)
also passed Rust 1.85, supported alloc-only compilation, strict stable Clippy
and strict-provenance Miri. That run's final detector shell failed because
`rg` was unavailable; the separate green detector run replaces that step.
No product unsafe code, representation or public API changes were needed.
To repeat the allocation checks, run `cargo test -p pbrs --test repeated_storage`
and `cargo test --release -p pbrs --test repeated_storage`.

## Held packed experiment

Both fixed-width borrowing candidates remain unshipped. They save a cold
encoding allocation and improve several copy workloads, but repeated warmed
lookups regress in both screens. The [full experiment](../held-packed-borrow-20261117/README.md)
retains the original and refined results. PK-14 remains open.

## Design limits

A public safe codec flag cannot authorize a generic unsafe cast. Fixed-width
borrowing must use concrete scalar implementations with initialized,
padding-free representations and the correct byte order. Big-endian and
custom codecs keep their ordinary encoding path.

A replacement for `Repeated<T>` must preserve the public mutable-`Vec`
behavior and the existing zero-copy `Vec` round trip. Removing the empty
mutable-slice allocation does not resolve the broader storage redesign.

## Generated-output control

[f4a4e204](https://github.com/mingley/pure-protobuf/commit/f4a4e204d48bb50a8317c9c2944601c3dc48840c)
separates reviewed current generator output from the frozen 05a3 record.
Reproducing the historical outputs confirmed that current differences consist
only of shared-byte length helpers and their typed-message hooks.

The [full parity and detecting gate](https://github.com/mingley/pure-protobuf/actions/runs/44037462514)
passes with the new control and rejects corrupted current output hashes,
input hashes and historical manifest bytes. The original runtime, selector,
legacy-cache and JSON assertions remain in place. This changes the fixture,
not map runtime behavior.

## Remaining release work

The current published versions remain `pbrs 0.2.1`, `pbrs-grpc 0.1.0` and
`protobuf-tonic 0.1.0`. A main-branch push does not publish crates.
The next release still needs final-source required CI, package rehearsals and
the applicable qualification in the [release checklist](../../release-readiness.md).
