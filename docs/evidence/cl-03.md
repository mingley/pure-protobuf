# CL-03 request header/timeout experiment

Date: 2026-09-28. Baseline artifact:
`target/client-perf/cl02-after-devloop.json` (after CL-02). Host: Apple M4 Pro,
macOS, shared/contended. Primary evidence is exact dev-loop allocation counts;
wall time is secondary and noisy.

## Hypothesis

Per-RPC request setup allocates in header map sizing, `grpc-timeout` formatting,
and URI construction. A small change should reduce allocation bytes or
instructions for `rpc.pbrs.unary` without changing wire-visible headers.

## Experiment

Unshipped patch saved locally at
`target/client-perf/cl03-reverted-experiment.diff`:

- sized request `HeaderMap` from actual fixed headers + metadata instead of
  always using the response-sized constant;
- encoded `grpc-timeout` into a stack buffer for `HeaderValue` instead of
  formatting a temporary `String`;
- tried a per-channel/per-method URI cache and reused cached `Uri` values
  across unary/server-stream attempts.

Focused tests passed during the experiment:

```sh
PATH="$PWD/target/pinned-protoc-build:$PATH" CARGO_BUILD_JOBS=3 \
  cargo test -p pbrs-grpc --lib wire::headers::tests
PATH="$PWD/target/pinned-protoc-build:$PATH" CARGO_BUILD_JOBS=3 \
  cargo test -p pbrs-grpc --lib timeout::tests
PATH="$PWD/target/pinned-protoc-build:$PATH" CARGO_BUILD_JOBS=3 \
  cargo test -p pbrs-grpc --lib client::channel::tests
```

## Measurement

Command:

```sh
PATH="$PWD/target/pinned-protoc-build:$PATH" \
  CARGO_BUILD_JOBS=3 \
  scripts/devloop.sh \
  --cells rpc.pbrs.unary,rpc.pbrs.server_stream \
  --baseline target/client-perf/cl02-after-devloop.json \
  --repeats 3 \
  --iters 2000 \
  --out target/client-perf/cl03-after-devloop.json
```

| Cell | Allocations/RPC before | Allocations/RPC after | Bytes/RPC before | Bytes/RPC after | Verdict |
|---|---:|---:|---:|---:|---|
| `rpc.pbrs.unary` | 56.335 | 56.345 | 55,031.480 | 54,472.040 | Bytes improved 1.02%, alloc count did not improve. |
| `rpc.pbrs.server_stream` | 73.335 | 73.335 | 65,932.480 | 65,372.480 | Bytes improved 0.85%, alloc count unchanged. |

Verdict: not shipped. The change did not meet the >=2% primary dev-loop win
rule, and the URI cache added a hot-path mutex for too little allocation-byte
gain. The existing dev-loop cells also do not set a timeout, so the stack
`grpc-timeout` encoder has no primary cell that proves a win.

## Follow-up

- Revisit CL-03 only with a dev-loop cell that exercises request deadlines and
  metadata, or with a codegen-owned static method descriptor that can prebuild
  the full `Uri`/header shape without a runtime map lock.
- H2-10/codegen static header work is the better place for full per-method
  templates; this worker should not hand-roll a map on the hot path without a
  qualifying allocation/instruction result.
