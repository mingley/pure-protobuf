# SB-32: unchanged tonic codegen transport matrix

The benchmark-only implementation registers **512 new**
`rpc.tonic_transport.*` cells: four transport combinations, the same 64 public
specimens and unary or four-message server streaming. The existing 512 typed
`rpc.adoption.*` IDs, codec corpus, fixtures, preparations and collectors remain
unchanged. Source is `8ca03da51ab3723f53858800ca5b8e2a33d0f448`, based on
`c9aef45c` after TC-30a integration. **SB-32 numeric qualification remains open.**
No release LTO, allocation profile, instruction profile or timing comparison
was captured in this implementation lane.

## Generated bindings and transport scope

The service-only `bench/devloop/proto/tonic_transport.proto` defines four
services around the existing corpus prost message types. Genuine pinned
protoc 35.1 and existing tonic-prost-build 0.14.6 generate ordinary, unchanged
clients and named services. External paths preserve ownership of all message
and Google protobuf types in `pbrs_adoption_corpus`; no second message model or
handwritten client codec replaces generated code.

| Profile | Generated client transport | Generated server transport |
|---|---|---|
| `reference_reference` | tonic Channel | tonic transport Server |
| `native_client_reference_server` | native Channel's opt-in tonic Service | tonic transport Server |
| `reference_client_native_server` | tonic Channel | native Router with TonicServer adapter |
| `native_native` | native Channel's opt-in tonic Service | native Router with TonicServer adapter |

Each profile calls the generated client directly. The generated server reads
every request field, checks the frozen checksum and echoes the complete
message. Streaming uses the same four replies and bounded eight-slot producer
recipe as the original reference handler. Clients read every field and check
the response count. Actual-network qualification also compares complete
decoded values and original encoded request/response bytes before warmup.

Both server paths inspect their actual accepted TCP socket. The reference
listener retains its frozen `TcpIncoming.with_nodelay(Some(true))` policy.
The benchmark's custom native Incoming reproduces the existing built-in
`tcp::tune` TCP_NODELAY=true policy, then reads the actual socket value and
addresses. This observes the custom Incoming, not built-in accept telemetry.
It adds no socket queue and changes no shipping transport default. Keepalive
remains unset and native/tonic message caps remain at their defaults.

Preparation, the full-network oracle, 100-operation warmup and server teardown
remain outside the existing exact allocation guard. The child runtime has two
workers. A new-prefix-only common FNV-1a input fingerprint is emitted by each
child and checked across N/2N and repeats. It identifies prepared inputs; it
is not a cryptographic hash. Existing IDs and collector reports are preserved.

## Final-source correctness evidence

The final-source devloop suite passed **17 tests**, including all **488**
eligible actual-network cells across all four combinations and both shapes.
The other **24** map cells remain visible in the 512-ID inventory: the frozen
native map encoding adds four bytes, so original equal-wire qualification
blocks those cells before network/timing even for the all-prost reference
profile. This preserves the existing PK-30 acceptance boundary.

Strict offline/locked all-target Clippy passed with `-D warnings`. Scoped
formatting includes build.rs, main.rs, the new leaf and lib.rs; source
whitespace checks passed. These are local correctness gates, not numeric
qualification, whole-workspace CI, minimum-Rust certification or a production
soak. Test-mode preflight returns before warmup and allocation/timing guards.

[validation.json](sb-32/validation.json) records the exact final source hashes,
test command and UTC times, raw log hashes, compiler/protoc pins and generated
binding/test-binary hashes. [preflight-inventory.json](sb-32/preflight-inventory.json)
retains all 512 IDs, 488 full-network records and 24 blocked IDs. Its rows come
from the final-source log, rather than an earlier test run. Initial duplicate
Google protobuf external-path and strict-lint attempts are retained beside
the final successful gates; both were corrected before the source pin.
