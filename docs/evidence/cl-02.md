# CL-02 unary path allocation trim

Date: 2026-09-28. Base baseline artifact:
`target/client-perf/cl-baseline-devloop.json` from
[`client-profiles.md`](client-profiles.md). Host: Apple M4 Pro, macOS,
shared/contended. Primary evidence is exact dev-loop allocation counts;
wall time is secondary and noisy on this host.

## Hypothesis

The default successful client path copied the static RPC path into every
`Response` before checking client response hooks. Most calls have no response
hooks, so that `String` allocation can be skipped while preserving hook-visible
path semantics when hooks exist.

The larger CL-02 goals (unboxed `Call` future and non-`watch` cancellation)
remain valid but require a bigger `Call`/`CallHandle` state-machine refactor to
preserve drop cancellation and detached handles across unary, server-streaming,
client-streaming and bidi shapes.

## Change

`pbrs-grpc/src/client/call.rs` now returns the response directly when
`Channel::response_interceptors` is empty. When hooks are present it still
stamps `ResponseParts::path` before running hooks.

## Measurement

Command:

```sh
PATH="$PWD/target/pinned-protoc-build:$PATH" \
  CARGO_BUILD_JOBS=3 \
  scripts/devloop.sh \
  --cells rpc.pbrs.unary,rpc.pbrs.server_stream \
  --baseline target/client-perf/cl-baseline-devloop.json \
  --repeats 3 \
  --iters 2000 \
  --out target/client-perf/cl02-after-devloop.json
```

| Cell | Allocations/RPC before | Allocations/RPC after | Delta | Bytes/RPC before | Bytes/RPC after | Delta |
|---|---:|---:|---:|---:|---:|---:|
| `rpc.pbrs.unary` | 57.330 | 56.335 | -1.74% | 55,059.160 | 55,031.480 | -0.05% |
| `rpc.pbrs.server_stream` | 74.335 | 73.335 | -1.35% | 65,963.480 | 65,932.480 | -0.05% |

Verdict: ships as a deterministic allocation removal (about one heap allocation
per default successful unary/server-stream RPC), not as a wall-time claim.
The dev-loop compare exited green; macOS instruction/syscall metrics were
`not_run`.

## Limits and follow-up

- Wall time regressed in this contended run (`+62%` unary, `+13%`
  server-stream) while allocation primaries improved; treat wall as noisy
  secondary evidence only.
- The boxed `Call` future and `watch` cancellation channel still account for
  remaining CL-02 scope. A follow-up should introduce a concrete `Call` future
  representation that keeps `CallHandle` cancellation semantics for all call
  shapes.
