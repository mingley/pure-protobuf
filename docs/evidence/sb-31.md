# SB-31: reproducible adoption map inputs and residual replay variation

Qualification date: 2026-10-02. **Instrumented dev-loop diagnostic; shared
managed Linux host; no performance win or claim-grade result.**

The input repair is qualified: independent processes produce identical common
map input bytes, and the collector enforces fingerprints across N/2N children,
repeats and new-report comparisons. **PK-31 remains blocked:** two reports from
the unchanged binary still fail the existing 1% codec control rule. Increasing
common N left residual instruction variation; a paired profile attributes most
of one difference to libc copying. No shipping map optimization is merged by
this work.

## Residual variation and attribution

The retained N=16 [control pilot](sb-31-pilot.json) and
[raw children](sb-31-pilot-raw.jsonl) show matching inputs but repeat instruction
ranges of 1.58% for map512 decode and 5.35% for map512 read-all. This motivated
using a larger common N. A separate [fresh-target pilot](sb-31-target-pilot.json)
([raw children](sb-31-target-pilot-raw.jsonl)) measured roughly 17.58 million
instructions/op and sized the collection budget; its one repeat is not a
qualification comparison.

At N=256, map512 fresh encode repeat ranges are only 0.0021%/0.0030%. However,
map512 read-all ranges are 3.97%/1.28%; the maximum range in the full matrix is
6.14% for pbrs map64 fully-read-clone in replay 2. Repeated instructions can
therefore vary even with identical input bytes and exact allocations.

Two map512 read-all 2N=512 profiles differ by 17,451,736 total instructions.
An unresolved libc routine at offset `0x162b40` accounts for 17,352,859 of that
difference (99.43%). Its disassembly is an AVX byte-copy implementation. Native
key-comparison, map merge, complete read-walk and stable-index sort self counts
match between those profiles. This supports address-dependent libc copying as
the dominant remaining cause in this pair; it does not prove one cause for all
failing rows or certify hardware retired-instruction behavior.

The raw instruction variation is not erased by the fingerprint check. PK-31

runtime candidate can satisfy the unchanged control rule. SB-20's larger noise

Historical SB-26 map reports used randomized common-wire ordering. Their old
source pins and artifacts are untouched, and they cannot retroactively qualify
this map optimization. This evidence also cannot be compared directly with
historical different-compiler, different-N map baselines.

## Reproduction

Use the source pin above, the locked manifests, genuine protoc 35.1 with the
pinned protobuf include checkout, and the tool versions in the summary. The
local toolchain environment was provisioned under
`/workspace/pure-protobuf/work/toolchain/env.sh`; full paths are retained in the
collection commands. Release compilation is retained in
[sb-31-collector-release-build.txt](sb-31-collector-release-build.txt).

```sh
cargo test --locked --manifest-path bench/devloop/adoption/Cargo.toml \
  --target-dir target/sb31-adoption -j2
cargo clippy --locked --manifest-path bench/devloop/adoption/Cargo.toml \
  --target-dir target/sb31-adoption -j2 --all-targets -- -D warnings
cargo test --locked --manifest-path bench/devloop/Cargo.toml \
  --target-dir target/sb31-devloop -j2
cargo clippy --locked --manifest-path bench/devloop/Cargo.toml \
  --target-dir target/sb31-devloop -j2 --all-targets -- -D warnings
cargo build --release --locked --manifest-path bench/devloop/Cargo.toml \
  --target-dir target/sb31-devloop -j2
python3 bench/devloop/adoption/generate.py --check

# Record the real Valgrind path before prepending the transparent wrapper.
export PBRS_REPLAY_VALGRIND="$(command -v valgrind)"
mkdir -p target/sb31-capture-bin
ln -s "$PWD/bench/devloop/adoption/capture-callgrind.py" \
  target/sb31-capture-bin/valgrind
export PATH="$PWD/target/sb31-capture-bin:$PATH"
export PBRS_DEVLOOP_COMMIT="$(git rev-parse HEAD)"
SB31_BIN="$PWD/target/sb31-devloop/release/devloop"
SB31_CELLS="$("$SB31_BIN" list | rg '^codec\.adoption\.' | \
  rg '\.maps\.' | cut -d ' ' -f1 | paste -sd, -)"
# Use fresh output paths; do not append to an existing raw evidence file.
export PBRS_REPLAY_RAW="$PWD/target/sb31-replay-1-raw.jsonl"
"$SB31_BIN" run --cells "$SB31_CELLS" --iters 256 --repeats 3 \
  --out target/sb31-replay-1.json
export PBRS_REPLAY_RAW="$PWD/target/sb31-replay-2-raw.jsonl"
"$SB31_BIN" run --cells "$SB31_CELLS" --iters 256 --repeats 3 \
  --out target/sb31-replay-2.json
"$SB31_BIN" compare --baseline target/sb31-replay-1.json \
  --current target/sb31-replay-2.json
"$SB31_BIN" compare --baseline target/sb31-replay-2.json \
  --current target/sb31-replay-1.json
```

Preserve comparison exit codes and all cells. The wrapper changes neither
Valgrind arguments nor the child result; it retains complete stderr and JSON
for raw replay audits. It does not make this shared host claim-grade or remove
the copy-path variability shown above.
