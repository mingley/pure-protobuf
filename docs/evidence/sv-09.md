## Attribution

The native prost 400-RPC whole-process profile contains 64,504,248 IR. The
libc copy routine at offset `0x162b40` accounts for 17,266,839 self IR (26.77%).
Its callers include dynamic service future construction (4,681,211 IR) and
client `server_streaming` future construction (4,439,931 IR), together 14.14%
of whole-process IR. These are full callgraph measurements, including setup;
they are not per-RPC differential shares or per-side production measurements.

Disassembly separately proves that native prost `DynService::dispatch`
allocates a 11,536-byte future and copies the full future from stack to heap.
The native client `server_streaming` constructor allocates and copies a
10,816-byte future. These sizes come from allocation and memcpy call arguments,
not an allocation-stack profiler. Response prost encoding contributes about
0.31% of whole-process IR to that copy routine; it remains a distinct codec
allocation candidate owned by CL-08.

Tokio worker self IR is 2.87%. Its inclusive share includes nested transport
and user work and must not be interpreted as scheduler self cost.

Allocation-stack tracing is `not_run`: both Memcheck xtree attempts failed
before workload execution because the stripped dynamic loader lacks the
required strcmp redirection without matching libc6-dbg. Raw startup stderr is
retained. There is no xtree allocation attribution. A sampled flamegraph is
also `not_run` because perf, samply and dtrace are unavailable. Full Callgrind
self, inclusive and caller reports provide the available instruction evidence.

## Bounded hypothesis and semantics

The recorded hypothesis skips the existing refill yield only when an
application response channel has already closed. Closed receivers may retain
queued messages, but no producer can add another message after the current
burst is drained. Live producers retain their existing yield and the
64-message burst limit. Wire-backed responses retain the original predicate:
the connection driver can advance them. The wider initial Wire=false patch
was superseded before any measurement.

Fixture `24d52a2b` covers closed bursts of 0/1/4/63/64/65/129/512 messages,
ordered successes before terminal error and metadata, bounded live producers,
and producer wakeup on response cancellation. Fixture `4a0c5a23` adds direct
wire-backed bidi echo progress, half-close completion and cancellation.
The superseded candidate passed 83 selected semantic integration tests,
including 5,000 seeded lifecycle scenarios. The narrowed candidate passed all
five dedicated SV09 tests. These validation scopes are separately retained.

## Early screen

The coordinator-approved paired primary screen ran at N=200/400, three repeats,
on 2026-10-02 from 20:06:21 to 20:06:35 UTC after all other heavy work was
paused. All 12 Callgrind children exited zero. Original reports and raw child
stderr retain full source and binary pins.

| Prost server stream metric | Baseline | Closed-channel gate | Change |
| --- | ---: | ---: | ---: |
| Instructions/RPC | 158772.300 | 156336.680 | -1.534% |
| Allocations/RPC | 57.025 | 57.010 | -0.026% |
| Heap bytes/RPC | 62632.640 | 62631.680 | -0.0015% |

The candidate is **rejected**: neither instruction nor allocation-count gain
reaches the unchanged 2% targeted-win minimum. The original comparator exits
zero because there is no regression beyond its existing 2% RPC limit; it does
not enforce a targeted-win minimum. Syscalls fell 7.847% and futex-family calls
fell 13.438%, but those secondary metrics do not satisfy the targeted-win rule.
No compressed or full 20-cell control capture was run after rejection. The
runtime edits were restored to baseline in `fc109a11`; both source experiment
commits and reproduction patches remain retained as evidence.

The rejected 400-RPC profile still spends 27.09% of whole-process IR in the
libc copy routine. Dynamic dispatch and client future-construction callers
account for 4,672,299 and 4,438,539 copy IR respectively. That confirms the
bounded yield change did not remove the larger future-copy bottleneck.

This is same-process, closed-loop development evidence. It does not establish
client/server production throughput or a leadership claim. SV09's matched
tonic instruction/byte floor and the full primary-control gate remain open.

## Retained evidence and reproduction

`sv-09/closed-yield-evidence.tar.gz` contains the original collector reports,
full raw child stderr, N/2N full callgraphs, before/after annotations,
constructor disassembly, build/check logs, metadata, tool/file hashes and the
exact transparent wrapper driver. Files preserve their original `work/`
relative paths. `sv-09/rejected-closed-channel-yield.patch` reconstructs the
narrowed runtime experiment from the pinned baseline. The separate
`sv-09/superseded-unmeasured-wire-false.patch` is retained with an explicit
unmeasured status. Binary hashes identify captured artifacts; binaries are not
bundled.

To reproduce the primary screen, build the pinned baseline and patched candidate
with the unchanged command and environment above. Place a symlink named
`valgrind` to `bench/devloop/adoption/capture-callgrind.py` first on PATH, set
`PBRS_REPLAY_VALGRIND` to the pinned real tool, `PBRS_REPLAY_RAW` to separate raw
JSONL paths and `PBRS_DEVLOOP_COMMIT` to each source pin, then run each frozen
binary with:

```sh
devloop run --cells rpc.prost.server_stream --iters 200 --repeats 3 --out REPORT.json
devloop compare --rpc --baseline BEFORE.json --current AFTER.json
```

Check the targeted 2% instruction/allocation-count win separately from the
original comparator's regression exit status. Missing allocation-stack and
sampled profiles remain `not_run`.
