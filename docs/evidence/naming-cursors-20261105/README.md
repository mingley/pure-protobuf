# Numbered type-name allocation

Generated names now remember the next numeric suffix for each repeated
prefix. The allocator also keeps the `View` and `Mut` strings it already
constructed when reserving a message name, rather than formatting them twice.
Public names and generated bytes stay unchanged in these controls.

The former numbered search restarted at two for every collision. Repeating
`A0000.B.X`, `A0001.B.X`, and so on therefore retried a growing list of occupied
names. Cursors remove those quadratic retries. Messages and enums need
separate cursors: a message can reject `BX_3` because `BX_3View` is occupied,
while an enum can still use the bare `BX_3`. Failed reservations change nothing.

## Measurements

The first 212 processes compare an isolated allocator overlay with core source
[`0ae8a43d`](https://github.com/mingley/pure-protobuf/commit/0ae8a43d3d08617c249c84a3f0d30f614494d70e).
It excludes concurrent boxing-selector and namespace changes. The CLI includes
`protoc`, generation and file handling; it does not measure consumer builds,
protobuf runtime work, RPCs or the final combined repository source.

The focused run has nine randomized baseline/candidate process pairs per row.
Lower wall-time ratios are better; ranges contain every pair.

| Input | Operation | Paired new / old wall time | Range |
|---|---|---:|---:|
| 1,024 repeated-prefix groups | Fresh output | 0.543 | 0.510–0.647 |
| 1,024 repeated-prefix groups | Unchanged output | 0.575 | 0.531–0.720 |
| 1,000 ordinary messages | Fresh output | 0.981 | 0.935–1.313 |
| 1,000 ordinary messages | Unchanged output | 1.001 | 0.886–1.044 |

Each repeated-prefix group declares `Axxxx`, its nested `B`, and `B.X`.
Two extra declarations occupy a numeric suffix and a message companion name.
All nine repeated-prefix pairs favor the new allocator. The earlier five-pair
screen also covers 64 and 256 groups: fresh ratios are 0.926 and 0.813,
respectively; the 64-group range crosses one.

Ordinary schemas retain mixed results. The initial five-pair fresh medians
are 1.050, 1.074 and 1.028 for 6, 100 and 1,000 messages, with all three ranges
crossing one. Its 1,000-message unchanged median is 1.012, and all five pairs
are above one (1.003–1.079). The longer focused run above does not clearly
repeat that slowdown. Neither run establishes a common-case speedup or absence
of a regression. Ratios are medians of paired ratios, not ratios of the
separately displayed baseline and candidate medians in the raw summaries.

All 212 allocator-overlay processes succeeded. Every baseline/candidate output tree has
identical Rust file contents for all seven inputs, including the mixed-kind
explicit-conflict control. The collector checked that the second invocation
preserved file bytes and mtimes. The retained per-capture tree is the observed
first-invocation snapshot; post-invocation mtime equality is a collector
assertion rather than a separately retained second snapshot.

## Combined default-generation cost

A separate five-pair run uses the combined core after the boxing selector,
safe-default option and namespace repairs, including the regenerated bindings.
The CLI leaves boxing selectors empty and `safe_message_defaults` disabled.
These 60 processes use the same original baseline and proto inputs.

| Ordinary messages | Fresh new / old wall time (range) | Unchanged new / old wall time (range) |
|---|---:|---:|
| 6 | 0.957 (0.892–1.136) | 1.024 (0.975–1.059) |
| 100 | 1.000 (0.928–1.056) | 1.018 (0.958–1.138) |
| 1,000 | 0.985 (0.893–1.850) | 0.945 (0.898–1.039) |

All ranges cross one. Small unchanged-output medians retain overhead; the
large fresh row has a slow outlier. The combined run does not establish a
broad generation speedup or absence of a regression.

Namespace qualification changes Rust spelling as intended, so output bytes
differ between source versions. The three generated totals grow from
136,464 to 136,777 bytes, 2,248,949 to 2,254,157, and 31,919,839 to 31,972,478.
Within each version, every repeated output is identical and retains mtimes.
This run retains both before/after output observations for those checks.
Functional generated-consumer parity is checked separately; byte differences
alone establish neither a feature mismatch nor equivalence.

## Correctness and source binding

The expanded naming unit passes in a release build with only `codegen` enabled.
The [generated-consumer fixture](../../../tests/proof/codegen_parity/src/type_collisions.rs)
also checks occupied `BX_2`, occupied `BX_3View`, later message suffixes, and
the enum that must still receive `BX_3`. Full integration of the concurrent
features has separate checks; this record does not claim that combined run.

Seventy selected baseline core inputs reconstruct from Git. The isolated candidate
changes only `src/codegen/naming.rs`, including its fixture test. Both builds
use the same adapted root-only workspace, dependencies and CLI source,
`default-features = false`, `features = ["codegen"]`, release optimization,
thin LTO and one
codegen unit. Rust is 1.99.1 with LLVM 23.1.1.

The combined build has 71 selected inputs, adding `src/codegen/boxed.rs` and
retaining its other changed sources as separate overlays. Its source hashes
still matched the working tree after capture. The same Cargo profile, CLI
source, compiler and lockfile are used. The packet distinguishes its source
and observations from the allocator-only experiment.

The baseline executable is reused from the earlier source-bound build. Its
70 original inputs match Git `0ae8a43d` exactly; its adapted source, compiler,
harness, lockfile and binary-hash records are retained. The candidate was built
fresh. An initial setup build accidentally included concurrent lower-file
boxing calls without their modules and failed; that source and log are kept
under `setup-failure`. The corrected isolated source was built and tested
before any timing. No failed generator process is omitted from the measured
campaigns.

Runs used one shared Linux x86_64 environment. Other local builds paused
during timing, but that does not establish host isolation. The blocking
process-tree timer and RSS sampler have observer costs; short CLI timings are
especially noisy. Selected source inventories are not filesystem-read traces
or hosted attestations. Executables, toolchain binaries and generated output
trees are not retained, so their recorded hashes cannot be independently
recomputed from this packet. No competitor ranking is established.

## Check and reproduce

From the repository root, with Git history containing `0ae8a43d`:

```sh
python3 docs/evidence/naming-cursors-20261105/check.py
```

The checker reads the archive without executing it, reconstructs selected
sources, verifies source/build/controller bindings, and recomputes all 272
process counts and paired results. It checks consistency of the observed output
hashes; reproducing the output requires rebuilding the executables.

The archive retains the proto corpora, CLI source, Cargo profiles, lockfiles,
build commands and timing controller. Its scripts use their original workspace
paths; choose a fresh output directory and adjust those paths before rebuilding.
