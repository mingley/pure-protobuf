# GN-02: generated code shrink evidence

This records the safe GN-02 slice completed in the GN-02/GN-03 shrink
worktree. The numbers are **dev-loop, contended host** diagnostics on macOS
arm64 with `CARGO_BUILD_JOBS=3`; they are not claim-grade performance results.

## Hypothesis

GN-01 identified generated source volume and always-emitted reflection/format
helpers as the top downstream compile-time costs. An accessor-only generation
profile should reduce generated bytes and compile time without changing default
output or hot binary codec behavior.

## Method

- Default pbrs/prost/v4 100-message baseline:
  `target/codegen-bench/gn0203-baseline-100-20260929T014406Z`.
- Accessor-only pbrs 100-message run:
  `target/codegen-bench/gn0203-lean-100-20260929T015000Z`.
- Accessor-only pbrs 1,000-message run:
  `target/codegen-bench/gn0203-lean-1000-20260929T015052Z`.
- Same-tree default pbrs 1,000-message comparison:
  `target/codegen-bench/gn0203-default-current-1000-20260929T015853Z`.
- Historical comparator rows for prost/v4 1,000-message compile/release are
  from SB-09 because the attempted pre-edit 1,000-message run was invalidated
  by source changes during measurement.

Accessor-only profile:

```sh
SB09_PBRS_EMIT_REFLECTION=0 SB09_PBRS_EMIT_JSON=0 SB09_PBRS_EMIT_TEXT=0 \
SB09_PBRS_RUNTIME_PROFILE=minimal \
  ./scripts/codegen-bench.sh --case <100|1000> --generators pbrs \
  --repeats 1 --jobs 3
```

## 100-message corpus

| Generator/profile | Generated Rust bytes | Clean check | Release build | Release binary |
|---|---:|---:|---:|---:|
| pbrs default before | 2,150,801 | 16.38 s | 54.49 s | 1,498,384 |
| pbrs accessor-only | 1,112,692 | 8.67 s | 20.03 s | 1,498,448 |
| prost-build | 41,797 | 5.62 s | 13.36 s | 826,192 |
| protoc `--rust_out` v4 | 2,011,405 | 5.51 s | 13.63 s | 1,108,992 |

Verdict: accessor-only pbrs cuts generated bytes by 48%, clean check by 47%,
and release build by 63% versus the pbrs default on the same 100-message
diagnostic. It still does not beat prost or v4 on clean check/release time.

## 1,000-message corpus

| Generator/profile | Generated Rust bytes | Clean check | Release build | Release binary |
|---|---:|---:|---:|---:|
| pbrs default, same-tree diagnostic | 34,130,773 | 51.70 s | 270.85 s | 9,424,112 |
| pbrs accessor-only | 10,980,049 | 40.55 s | 241.34 s | 9,424,176 |
| prost-build (SB-09) | 413 KiB | 6.5 s | 82.3 s | not repeated in this run |
| protoc `--rust_out` v4 (SB-09) | 20.1 MiB | 16.1 s | 36.1 s | not repeated in this run |

Verdict: accessor-only pbrs cuts generated bytes by 68% and improves the
same-tree clean/release build diagnostics, but pbrs still loses B4/B6 to prost
and v4 on the 1,000-message corpus. The remaining cost is the binary
parse/encode/accessor surface, which this worker could not move into shared
helpers because `src/codegen/{parse,encode}.rs` were explicitly out of scope.

## Auto-trait recursion warning

The nightly 1,000-message check still emits
`recursion_depth_exceeding_limit` while proving `Message0600View<'msg>: Sync`.
The warning is rooted in the public `Message`/`MessageView` `Send + Sync`
bounds and the generated `LazyMsg<PreviousMessage>` chain. A safe fix likely
requires either changing runtime/message trait bounds or adding audited manual
auto-trait impls around lazy message storage; both are outside this worker's
allowed write scope and the latter would introduce `unsafe`.

## Codec/dev-loop status

The dev-loop must run with `target/pinned-protoc-build` first in `PATH` because
`v4_tat/build.rs` invokes `Command::new("protoc")`. After clearing only the
local `bench/devloop` `v4_tat` build artifacts and using that pinned PATH, this
smoke passed:

```sh
PATH=$PWD/target/pinned-protoc-build:$PATH CARGO_BUILD_JOBS=3 \
  ./scripts/devloop.sh \
  --cells codec.pbrs.fresh_encode,codec.pbrs.cached_encode,codec.pbrs.owned_decode,codec.pbrs.parse_touch \
  --iters 1000 --repeats 3 --out target/devloop/gn0203-codec-smoke.json
```

Deterministic counters matched the expected pbrs shapes:

| Cell | Allocations/op | Bytes/op | Copy counts |
|---|---:|---:|---|
| `codec.pbrs.fresh_encode` | 6.4 | 187.8 | emit 13 calls / 55 bytes |
| `codec.pbrs.cached_encode` | 1.0 | 87.0 | emit 12 calls / 53 bytes |
| `codec.pbrs.owned_decode` | 7.0 | 1072.0 | wire 1 call / 87 bytes |
| `codec.pbrs.parse_touch` | 12.0 | 1216.0 | wire 1 call / 87 bytes |

No baseline compare was claimed from this smoke. The default generated output
is byte-identical, and the accessor-only profile changes optional
JSON/text/reflection methods, not binary parse/encode emission.

## Remaining GN-02 work

- Move parse/encode per-field logic into shared helpers after coordination with
  the codec worker that owns `src/codegen/parse.rs` and `src/codegen/encode.rs`.
- Collapse or reduce generated `MessageView`/`MessageMut` impl duplication only
  after deciding how to preserve the current public API and trait bounds.
- Resolve the deep auto-trait recursion warning in runtime/message/lazy storage
  with a reviewed design.
