# Generator and server scaling

## Generate source by file

The generator groups declarations by source file and checks each file's
eligibility once per target. A shared matcher also serves public imports.
Output paths and bytes matched across 12 fixtures with reordered inputs
and one or two workers. The fixtures cover interleaved declarations,
aliases, imports and services. [Correctness](https://github.com/mingley/pure-protobuf/actions/runs/44610722177)

| Workload | One-worker CPU reduction | Two-worker CPU reduction |
| --- | ---: | ---: |
| 1,000 messages, lean | 7.9% | 16.9% |
| 1,000 interleaved messages | 7.1% | 14.9% |
| 128 source files | 29.0% | 30.8% |
| 512 source files | 44.4% | 48.9% |

The 512-file case requested 68,583 allocations with one worker, down from
597,479. All figures compare pbrs builds on one shared runner with Rust
1.100.0. In the same-descriptor one-worker comparison, pbrs still used
3.03× Prost's CPU for 1,000 messages and 9.30× for 128 files. The generators
emit different APIs and amounts of source. [Paired generator samples](https://github.com/mingley/pure-protobuf/actions/runs/44611017706/artifacts/14573096462)

Exact file names now resolve through the existing index before suffix
matching. Against the file-planning revision above, this saved another
18–19% CPU on 128 files and 32% on 512 files. All 24 paired CPU samples for
these two workloads improved. The 1,000-message default and lean controls
stayed close to their previous medians, and all generated files matched.
[Exact-target samples](https://github.com/mingley/pure-protobuf/actions/runs/44614735245/artifacts/14574058756)

## Native RPC storage

The native server keeps the URI and receive stream after admission.
Metadata and connection context already carry the information exposed to
handlers. The native `Rpc` measured 504 bytes, down from 640. Cached unary,
owned unary and two-reply streaming each requested 680 fewer heap bytes
per warm RPC at the same allocation count. [Allocation samples](https://github.com/mingley/pure-protobuf/actions/runs/44610497592/artifacts/14572856585)

The TCP screen held the client and Prost codec fixed. Candidate/base
median throughput ranged from 0.994× to 1.011× across four cases.
Multiplexed stream throughput relative to tonic was 0.748× in the earlier
screen and 1.005× in this screen, on different shared runners. Dedicated
hosts are needed to resolve that case. [Earlier TCP samples](https://github.com/mingley/pure-protobuf/actions/runs/44609914183/artifacts/14571838930)

## Fully queued client uploads

When the producer has finished before dispatch, the client validates the
whole upload, reuses its frame sizes and sends the last batch directly.
With Prost messages on a fixed native server, the four-message case saved 1.04–1.35
allocation requests per RPC. The 16-message case saved 1.22–1.29. Each
message was 512 bytes. The paired throughput medians stayed within 0.7%
of the previous path. The native client led tonic in all six pairs for
these two cases. The 64-message live upload still measured 0.777× tonic's
throughput and 1.53× its p99 latency at the paired median.
[Matched TCP samples](https://github.com/mingley/pure-protobuf/actions/runs/44610958534/artifacts/14574095631)

## First encode of parsed packed int64

Canonical packed `int64` runs reuse validated wire bytes. An overlong
encoding keeps the canonical prefix and normalizes the suffix. The focused
owned-output probe benchmarked fresh messages across nine paired blocks
on Rust 1.100.0.

| Values | Prior pbrs | pbrs | Prost | upb |
| --- | ---: | ---: | ---: | ---: |
| 1 | 75.64 ns | 18.41 ns | 19.25 ns | 52.56 ns |
| 16 | 84.58 ns | 39.66 ns | 57.58 ns | 65.30 ns |
| 256 | 494.15 ns | 69.39 ns | 796.85 ns | 894.83 ns |

Late overlong normalization fell from 504.95 ns to 87.57 ns. The
mixed-width full-read median improved 4.4% across pairs. Small
owned-output and 256-value parse controls had paired ranges that crossed
parity. [Raw samples and configurations](https://github.com/mingley/pure-protobuf/actions/runs/44614745018/artifacts/14573949022)

## Owned-output codec baseline

The supported `owned-output` survey on Rust 1.100.0 passed all 28 fixtures
with pbrs, Prost and upb returning owned bytes for first and repeated
encodes. pbrs led upb on all 28 owned decode, full-read and repeated-encode
medians and 25 first-encode medians. The remaining first encodes were two
packed cases and a 4 KiB string. Prost led on 11 full-read medians and
15 first-encode medians. These are fixed-order samples on one logical CPU.
