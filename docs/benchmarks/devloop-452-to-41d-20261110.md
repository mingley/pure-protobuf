# Dev-loop advisory comparison, November 10

The [dev-loop run](https://github.com/mingley/pure-protobuf/actions/runs/42761599543)
compared base `452d2d52c005d09d44c6531a245542b5623d68e9` with head
`41d94325b8aa48b10b31fb6709c1a41dbc44a72a`, which includes the drop-only cancellation change.
Both measurements and evidence validation succeeded, with 1,634 common cells
and none added or removed. The workflow passed, but its comparison exited **1**
and is advisory. Hardware instruction counts were unavailable (`not_run`);
this run does not establish CPU speed, latency or an overall ranking.

The comparator reported 534 threshold-exceeding metric rows: 198 syscall and
336 `locks` proxy rows. It also printed 518 improvements (189 syscall and
329 `locks` proxy rows) and eight additional absolute `locks` budget
overruns. No allocation metric exceeded its comparison threshold. These are
metric rows, not unique benchmark cells or wins against tonic. All 1,060
printed rows cover 719 distinct cells. The [retained JSON](devloop-452-to-41d-20261110.json)
preserves every printed row in order; the original artifact contains both
complete reports and logs.

The eight overrun cells are `pick_first`, `round_robin`,
`weighted_round_robin`, `ring_hash`, `least_request`, `priority`,
`outlier_detection` and `random_subsetting_experimental`. Each reported
0.0005 against a zero `locks` budget. The `locks` field is a process-wide
`strace` count of futex calls, including setup, wakes and unsuccessful waits;
it is not a count of lock acquisitions. These shared-runner observations need
investigation and do not establish their cause or application impact.

These are specific fixtures from the same report, not a CPU benchmark. Query
`d4.v6` is depth 4, variant 6. Codec rows are allocations and requested bytes
per operation; RPC rows are medians per RPC and include work by both client and
server in one process. Each value below is base → head.

Fresh encode constructs and drops a fresh message tree as well as encoding it.
Owned decode decodes and drops a message from the common wire. Unary RPCs use
the same schema-qualified input, loopback TCP and two Tokio workers. A
full-value response is validated before warmup; measured responses are read
and checked. These selected pbrs Query codec fixtures request more allocations
and bytes than the corresponding Prost fixtures. Instrumentation and scheduling
affect RPC medians. The counting allocator records successful allocation and
reallocation requests and requested sizes, not live or peak memory.
