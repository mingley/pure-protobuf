# Repository audit — 2026-09-29

The repository has a substantial protobuf and gRPC implementation. Its next
constraint is trustworthy, current evidence: some important comparisons are
unfinished, the original shared-consumer suite has a correctness regression,
and the plan still sent contributors toward completed or rejected work.

The route to performance leadership is to restore correctness, finish fair
measurements, optimize the measured client/server costs, and reproduce results
on dedicated hosts. The [current queue](../TODO.md) gives the assignments;
the [performance program](plan/world-class/README.md) defines the outcomes.

## Scope and method

This audit reviewed committed `main` at
[`37683917c65fd06082a392f07e4d71bd587b18b9`](https://github.com/mingley/pure-protobuf/tree/37683917c65fd06082a392f07e4d71bd587b18b9).
Three parallel reviewers covered transport/operations, codec/codegen/kernel,
and benchmarks/evidence. A coordinating review covered CI, release/support
policy, task dependencies and documentation navigation. Reviewers then
cross-checked the revised plan.

The audit used source, tests, task acceptance criteria, recorded results and
the baseline's actual GitHub Actions logs. It did not rerun long benchmark,
fuzz or soak campaigns, and it is not a security certification or exhaustive
line-by-line proof. Uncommitted TCP work and existing worktrees in the user's
checkout were excluded; edits were made in an isolated worktree.

## Correctness and CI

At the audited revision:

- [CI run 36594564013](https://github.com/mingley/pure-protobuf/actions/runs/36594564013)
  passed conformance, Go/C++ interop jobs, MSRV, macOS, dependency audit,
  package consumers and generated-output checks. The main test job passed
  workspace tests, then failed `cargo doc --workspace --no-deps` with
  `RUSTDOCFLAGS='-D warnings'`.
- That rustdoc failure came from public documentation linking private
  `DynamicTable` and `merge_dynamic_loop` items, plus a redundant explicit
  `DynamicMessage` link in [src/table.rs](../src/table.rs). This update
  corrects those links without changing parser behavior.
- [Compatibility run 36594563929](https://github.com/mingley/pure-protobuf/actions/runs/36594563929)
  failed `test_map_int32_enum`: the map reports length one, but iteration
  yields no element. The run stopped after the first of 19 consumer crates
  (34 tests passed, one failed). Historical all-green counts are not current
  qualification.

Source inspection traces the enum-map failure to the conversion boundary:
[runtime/map.rs](../src/runtime/map.rs) stores the four-byte enum through the
integer field kind, while [runtime/reflect.rs](../src/runtime/reflect.rs)
recognizes primitive type identities and returns no view for that enum.
[map.rs](../src/map.rs) then skips the entry. QG-05 must restore a sound typed
enum conversion hook, not the removed arbitrary four-byte transmute fallback.
It must rerun all 19 original consumer crates and applicable Miri checks.

The `compatibility` workflow also has scheduled/manual lanes. A skipped
fuzz/target/sanitizer job on this push is missing evidence, not a pass. The
[recorded five-minute fuzz campaign](evidence/fuzz-2026-09-28.md) is useful
and found real bugs; it does not satisfy a 24 CPU-hour campaign.

## Architecture and product boundaries

The [HTTP/2 profile](evidence/h2-costs.md) concluded **NO-GO** for building a
new engine. A completed H2-03 design accidentally made H2-04 appear ready.
H2-04 is now explicitly blocked; H2-16 requires a reviewed go decision backed
by at least 15% modeled gain on primary client/server cells or a demonstrated
correctness/design blocker. Replacing `h2` is not a prerequisite for proving
that the current transport is competitive.

Similarly, the runtime seam and per-core experiment do not show that per-core
execution wins every workload. Inline user-handler polling can block other
streams; preserve scheduler fairness while measuring any dispatch change.
Compression, TLS, allocation, copies and scheduling must be attributed
separately before choosing the next optimization.

The plugin-generated message path and the official `rust_out` compatibility
runtime are different. The latter still has incomplete MiniTables, arena,
extension, equality/debug and unknown-field behavior. Broad upb replacement
claims remain in the UK lane. Edition 2024 has a defined generated subset;
full typed extensions and complete conformance remain open. A Rust `.proto`
frontend and xDS are additional programs, not evidence that today's gRPC
client/server is faster.

Resource limits also need precise language. The `h2` send-buffer limit is
per stream, while current builders couple it to a shared byte tracker.
Protocol-buffer estimates omit application queues, retained backing buffers,
TLS, allocator and socket costs. The [resource guide](resource-budgets.md)
now states that boundary. QG-06 covers the shipping backend's 24-hour
slow-reader/cancellation/churn/overload exercise, separate from QG-03's future
engine soak. It also checks builder ordering and the coupled budget knobs.

## Plan and documentation changes

The revised queue prioritizes correctness and measurement, followed by
current-backend optimization and reproducible campaigns. Task cards specify
deliverables, dependencies, write scope and acceptance evidence. This update:

- reopens SB-21 and SB-23 where accepted work was incomplete;
- retains BM-03 as active prerequisite work, removing a reconciliation cycle
  with SB-15;
- adds QG-05/06/07, SB-24/25 and H2-16, and attaches required gates to the
  claim campaigns;
- blocks H2-04 after the recorded no-go;
- returns GN-05, UK-02 and XD-01 to in-progress review because their drafts
  have not met their recorded approval acceptance criteria;
- replaces the stale initial wave and duplicated card index with
  `scripts/plan-status.py`;
- extends the plan linter to catch cycles hidden by legacy reconciliation.

Documentation now routes readers from the README to task guides, API
reference, current status, performance evidence or contributor work.
Historical plans and experiments are labeled. The greeter uses a compact
error-lifecycle table; its tests preserve lifecycle coverage without pinning
whole sentences. Invalid guide calls were corrected. QG-07 addresses the
remaining tooling gap: syntax checks alone cannot catch nonexistent APIs,
so guide recipes should come from compiled examples or fixtures.

The audit does not rename crates, change runtime defaults, implement the
enum-map fix, launch paid hosts, publish packages or submit upstream work.
Those actions remain in their own bounded tasks.
